# 度量自检铁律（M3）：先验证你的尺子，再信你的数字

## 为什么要有这一条（血的教训）

2026-08-29 一次 skill 有效性评估，**连续三次度量失真**：

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | skill 名子串计数 | ❌ `memory` 命中 122 万次、`python` 101 万次 —— 155 个全判「活跃」，报告 100% 假 |
| v2 | 155 路 alternation 正则 | ❌ 跑 12 分钟没结束，性能崩 |
| v3 | token 提取 + set 查表 + 限定扫描范围 | ✅ 176 秒，数字合理 |

**更糟的是：v1 的输出看起来完全合理**（"155 个全活跃"），没有任何报错，如果不是我多看了一眼那个 122 万，结论就交付了。

历史审计：近 7 天同类误报**至少 7 次**——
08-23 编码误报（按 8 字节截断 UTF-8 误判 GBK）、08-24 路径 bug 导致 4 个标签误报缺失、
08-25 把 50+ 研究信号全误判成生产信号、08-29 本轮 3 次。
**M1（扫描器元测试）和 challenge_gate（产物质疑）都没止住**——它们管的是「扫描器能不能扫到」和「产物格式对不对」，
缺的正是这一环：**用来测量的尺子本身准不准**。

## 铁律：三关不过，禁止下结论

产出任何统计数字前，三关必须全过：

### ① 正例关（漏检检测）
**已知应该命中的样本，必须命中。**
- 例：评估 skill 引用，已知 `tqsdk-trading-and-data` 肯定被提到 → 必须出现在结果里
- 例：扫前视函数，先造一个含 `iloc[i+1]` 的样本 → 扫描器必须报出来
- 判定：正例命中数 < 预期 → 口径错/漏检，**结论作废**

### ② 负例关（污染检测）
**已知不该命中的，必须为零。**
- 例：幽灵名字 `zzz-no-such-skill-xyz` 命中必须为 0
- 例：扫"非 PA 指标"，纯 `range` 表达的样本不得被报
- 判定：负例命中 > 0 → 度量被污染，**结论作废**

### ③ 数量级关（上界校验）
**结果必须有合理性上界，超界即判污染。**
- 经验公式：单条目计数上界 ≈ `扫描文件数 × 50`（可按场景调）
- 例：扫 13518 个文件，某个名字命中 122 万次 = 每文件平均 90 次 → 必然是通用词污染
- 判定：超上界 → 报警并列出超界条目，**结论作废**

## 什么时候用

- ✅ 写任何「扫全库计数」的脚本（覆盖率、缺失项、引用数、命中率）
- ✅ 拿到一个统计结论准备下判断/写报告/交付前
- ✅ 审计器/扫描器新增检查项时（配合 M1）
- ✅ **信号函数重写/新增后**（见 S4：触发量回归，08-30 两次人肉发现归零后固化）
- ❌ 不需要：单次确定性查询（查一个文件的某行）、标准库调用

## 场景扩展 S4：信号触发量回归（2026-08-30 教训）

**背景**：08-29 提纯统计出 HS_TOP/HS_BOTTOM/SHRINK_STAIRS 十年 n=0（量化错误）、
08-30 DUELING_LINES 重写首版归零（把"60 根窗口总振幅「当」收敛区宽度"）——
**全是人肉发现**。触发量本身就是度量结果，归零/骤降必须自动报警。

**铁律（信号函数重写四查）**：
1. **触发量回归**：重写/新增后必跑探针对比基准 n；**归零或骤降 >90% = 正例关失败，禁止交付**
2. **逐条件打点**：归零/骤降时用探针自动统计每个 continue 条件拦截样本数，定位卡死条件（不再人肉读代码）
3. **合成正例**：构造含明确形态的合成序列必须命中（M3 正例关的形态版）
4. **真数据触发量**：必须从 0 恢复为正常量级才算修复（HS 87/500、SHRINK 1648/1897 为正常量级参考）

**工具**：`python run_py.py experiments/_cond_probe.py --fn <信号函数> --pkl <pkl> [--expect <基准n>]`
（AST 改写 `if cond: continue` → 计数，输出逐条件拦截分布 + 回归判定）
元测试：`experiments/_verify_cond_probe.py`（正例不误报 / 反例自动定位 / 幽灵明确报错）

## 反模式清单（踩过的坑）

| 反模式 | 症状 | 正确做法 |
|---|---|---|
| **通用词子串计数** | `memory`/`python`/`code`/`git` 命中上百万次 | 只在特定上下文计数（如 `skill <名>`、`skills/<名>`）；或只信任多段名（`a-stock-selector`） |
| **超长 alternation 正则** | 155 路 alternation 在大文件上 12 分钟跑不完 | 抓 token → set 查表（O(1)）；或先用子串快筛再精匹配 |
| **无上界输出** | 数字离谱但没人报警 | 写死上界并在代码里 assert/报警 |
| **只看结果不看分布** | "155 个全活跃"看起来很顺 | 必看最大值与分布，最大值异常先查度量 |
| **拿度量结果直接当结论** | 误删/误判 | 先跑三关，再下结论 |
| **信号重写后不查触发量** | 重写归零/骤降还交付（HS 十年 0、DUELING 首版 0） | 必跑探针做触发量回归（S4） |
| **窗口总振幅当结构宽度** | DUELING 收敛判定用 60 根总振幅 → 必然 >3×单根 RNG → 全卡死 | 结构宽度用两线间距/结构位间距，不是窗口振幅 |

## 检查点

- **写代码时**：先定义正例/负例/上界三个常量，再写扫描逻辑
- **跑完之后**：看最大值与分布，异常先查度量不下结论
- **交付之前**：`metric_selftest_passed` 必须为 true；为 false 时结论只能写"度量不可信，待修"，不得输出具体数字

## 场景扩展 S5：有效样本量关（2026-09-18 环境闸门教训）

前面三关管「尺子准不准（口径/污染/上界）」，本关管**第 4 件**：**这把尺子有多少个独立刻度**。

**问题**：统计量报 `n=50`，但**真实有效独立样本量只有 6** —— 因为滚动窗口内观测高度重叠
（步长 1 日 / 前视 10 日 ⇒ 相邻观测共享 9/10 的区间），实现却把每次观测当独立样本累加计数。
后果：SE 被低估 2.9 倍 ⇒ 阈值显得「有意义」，实际远小于噪声。判据退化为抛硬币。

**铁律**：报 n 必须报 **n_eff（有效独立样本量）**。

| 场景 | n_eff 估法 |
|---|---|
| 滚动/重叠窗口 + 前视步长 h | `n_eff ≈ 窗口长度 ÷ h`（本例 60/10 = 6） |
| 分组比较且组内时间聚集 | 组内按**非重叠块**计数，禁按行数计数 |
| 自相关序列 | n_eff ≈ n × (1−ρ)/(1+ρ) |

**配套两条**：
1. **阈值必须 ≥2×SE_eff**（`SE_eff = sqrt(0.25/n_eff)`）。本例阈值 0.03 vs 2×0.2041 = 0.408，差 **13.6 倍** ⇒ 落在噪声带深处。
2. **交叉验证法（可作 S5 的「数量级关」）**：算 `实测值 std ÷ 理论 SE_eff`，
   若 ≈1.0 即**反推真实有效样本数**并与申报 n 比对。本例实测 `std/SE_eff = 1.000`
   ⇒ 精确反推 n_eff = 6.0，**数值自证** n=50 是虚报。

**判据过宽同样适用**：给出「有效样本量」结论时，须能回答「什么条件下这个 n 算虚高」
（答：`申报 n / n_eff ≥ 2` 即须标注）。

**工具**：`_diag/v14_env_gate_validity.py`（六节审计模板，含噪声带/持久性/随机基准/分年/时间聚集/层级混淆）。
**兄弟闸**：WB 大脑 **G6 扩容（2026-09-18）**「判据有效样本量」条；PA 铁律 **R30**。

**判例**：`environment_quality`（PA 环境闸门）阈值 ±0.03 = 0.147×SE_eff → 2026-09-18 判无统计资格，
由「否决」降级为「提示」。
