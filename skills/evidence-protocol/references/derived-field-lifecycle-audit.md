# 派生字段生命周期审计

## 何时用

两类高发缺陷，同属「**单一源头的写入完整性**」家族：

| 病类 | 症状 | 典型触发词 |
|---|---|---|
| **派生键失同步** | 由 A 算出的 B（如 `win_pct` 由 `win` 派生）在 A 被覆盖后未重算 ⇒ **同一行内自相矛盾** | 派生字段/派生键、覆盖未重算、自相矛盾、值域冲突、None 空洞 |
| **唯一源头静默降级** | 源头文件被整体重写／写回旧版 ⇒ 下游拿到**残缺数据且不报错** | 唯一源头、整体重写、静默降级、记录数骤降、切数据→被消费 |

> **共同根因**：写入点未穷举。**若 B 由 A 派生，则 A 的每个写入点都必须紧跟 B 的重算；分支数即重算点数。**

---

## 铁律（血泪换的）

1. **分支数 = 重算点数**。一个覆盖函数有几个写入分支（既有行覆盖 / 注入新行 / 批量更新…），就必须补几处重算。**只补一处必然漏**（2026-09-29 实证：`apply_prod` 两分支，补一处仍漏）。
2. **探针必须带阴性对照**。只跑正例的探针是「空转通过」—— 必须证明**旧实现会失败**，否则判据没有区分力。
3. **断言前先证输入非空**。凡「不含 X」型断言，输入为空时**恒真** ⇒ 必须加「文案/值非空」前置断言。
4. **护栏只能防走本脚本的降级，防不住外部直接覆盖**。文件级护栏要判「**源头文件属性**」（version 禁回退、必留 caliber_note），不能只在生成器内部自保。
5. **先量化丢失面再动手**。用 DB/备份做三方对照，只读探针先出数，**再**决定怎么修 —— 禁凭印象直接改。
6. **临时取证产物禁落会被机检扫描的目录**（根级 `*_tmp.json` 会引入 C49 FAIL）。取 JSON 直接管道给解析器，或落 `_diag/` 并即刻消费。

## 工作流

### 阶段 1 · 取证（只读，禁改）

1. **定位派生关系**：搜同名/近名字段（`win` → `win_pct`/`win_cnt`/`win_unit`），读实现找出「谁在算什么」。
2. **穷举写入点**：`grep -n` 目标字段的全部赋值行（`X["win"] =`、`it.update(`、`dict(...)` 构造…），**按写入分支计数**。
3. **量化不一致面**：写只读探针，对每行**重算**派生值并与**落盘值**逐字段比对（浮点容差 1e-6）。
   输出：不一致行数 / 三键齐全行数 / 分派分布。
4. **判唯一源头 + 影响面**：找出「谁在读源头」的全部消费方；问三件事：
   - 谁在读？（消费方清点）
   - 降级时**报不报**？（`raise` 仅在空列表 ⇒ 4 条不报 = 静默降级）
   - 护栏**覆盖面**到哪？（脚本内自保 ≠ 防外部覆盖）

**产出物**：`_diag/_probe_<主题>_<日期>.py`（保留，可复用）+ 丢失面数字。

### 阶段 2 · 修复（先备份、后改、必回读）

1. **备份**：`shutil.copy2(src, src + ".bak_<标签>_<时间戳>")`。
2. **修实现**：在**每个**写入分支后补重算调用（复用既有单一实现，**禁写第二份判据**）。
3. **就地补数据**：对存量行重算（幂等：重复运行结果一致）。
4. **落盘**：`temp` + `os.replace`（原子），**禁止** `open(w)` 直写。
5. **回读校验**：重新读盘，逐字段再比对；**异常数 != 0 即判失败并提示回滚路径**。
6. **若源头整体重写**：用**权威源（DB/备份）重建**目标区段，**保留**同文件内其他区段（聚合快照等）—— 禁整文件覆盖。

### 阶段 3 · 阴阳对照（准入门槛）

必建 `_diag/_<主题>_selftest_<日期>.py`，至少三例：

| 用例 | 期望 |
|---|---|
| T1 正例：新实现后派生键 ≡ 重算值 | 异常 **0** |
| T2 阴例：旧实现（修前逻辑复刻）喂同一夹具 | 异常 **> 0**（否则探针无区分力 ⇒ 报 FAIL） |
| T3 构造样本：显式「A 变化」的行（如 win 0.20→59.05）走旧实现 | 异常 **> 0** |

> T2/T3 若为 0，**不要**调低标准 —— 说明夹具未覆盖被覆盖行，**先修夹具**。

### 阶段 4 · 登记与收尾

- 经验库 `problem_experience.db` 补录（**解决后当场**，R3/R20）：
  `experience(id,category,title,symptom,root_cause,solution,gate,status,source_date,keywords)`
  按 `title` 精确去重保幂等。
- 字段语义登记升版（新增「派生键须与源字段同生命周期」类规则）。
- 待办 note 走**追加式**入口（`todo_note_append.py --note-file`），**禁** `todo_ctl update --note`（覆盖式会静默截断历史）。
- 机检对比基线：**逐项与起始相同 = 零回归**（PASS/WARN/FAIL 三数都要对）。

## 检查表（逐条打勾，禁跳）

```
□ 写入点已穷举？分支数 == 重算点数？
□ 只读探针已量化不一致面（有数字，非"看起来对"）？
□ 唯一源头的消费方已清点？降级是否报错？护栏覆盖面？
□ 备份在做改动之前？备份路径已记录？
□ temp + os.replace（非直接 w 写）？
□ 落盘后回读逐字段校验？异常数 == 0？
□ 阴阳对照 T1=0 且 T2/T3>0（探针有区分力）？
□ 机检 PASS/WARN/FAIL 与基线逐项相同（零回归）？
□ 经验库已补录（幂等去重）？note 走追加式？
□ 一次性脚本已归档？可复用探针保留？临时件未落扫描面？
```

## 常见陷阱

| 陷阱 | 后果 | 正解 |
|---|---|---|
| 只看生成器不看存量数据 | 生成器修了但**现盘仍是坏的** | 实现修复 **+** 存量重算，两件都要 |
| 只测正例 | 探针无区分力，空转通过 | 必带 T2/T3 阴例 |
| 用 `grep X` 判定字段存在 | 撞上注释/docstring 噪声（实测命中率 <10%） | 用 **AST 代码级**字面量 + 整串判据 |
| 判据用「值域」区分语义 | 同量纲值天然跨域 ⇒ 误报 >50% | 按**数形态**（整数/小数）三分，非按区间 |
| 已死文件仍被登记为消费方 | 改了**已归档**的代码，真消费方未动 | 消费点登记必须与**文件存活状态同源** |
| 假设重跑生成器能还原 | 累积型数据（promote_*）**结构上无法还原** ⇒ 静默砍数据 | 就地补字段；不加重跑逃生口 |
| 「不可判」当「通过」 | WARN/不可判按未验证处理 | 判据报 WARN 时**按未验证**，不得下通过结论 |
